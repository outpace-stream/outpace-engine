# Outpace 1.2.0

For publication status and downloads, see the
[GitHub Release](https://github.com/outpace-stream/outpace-engine/releases/tag/v1.2.0).
These notes accompany the reviewed release commit; source documentation can precede publication.

Outpace 1.2.0 is a minor release. It adds opt-in casting to DLNA/UPnP renderers and an opt-in
SOCKS5 outbound proxy, reports why a stream start is slow or failed, refuses VOD downloads that
would fill the disk, and paces DHT lookups by replies. Both new features are off by default. The
native start routes now return a JSON error body; their status codes are unchanged.

## Features

- **Casting to DLNA/UPnP renderers**
  ([#488](https://github.com/outpace-stream/outpace-engine/pull/488), closes #484). With
  `OUTPACE_ENABLE_CAST=1`, `GET /cast/targets` discovers media renderers on the LAN with one SSDP
  search (cached for 60 s), and `POST /cast/targets/{target}/play` starts a live stream and points
  the renderer at a per-cast URL that serves the shared session. `stop` and `status` complete the
  API. Live streams only. `OUTPACE_BIND` must be reachable from the renderer; a loopback bind
  answers `409 loopback_bind`. A renderer that refuses `video/mp2t` is offered `video/mpeg` once.
  At most 16 renderers and 16 concurrent casts; a new cast at capacity is refused rather than
  evicting one. Control routes reject cross-site browser requests. See
  [Casting](https://github.com/outpace-stream/outpace-engine/wiki/Casting).
- **Optional SOCKS5 outbound proxy**
  ([#492](https://github.com/outpace-stream/outpace-engine/pull/492), closes #486).
  `OUTPACE_PROXY=socks5://[user:password@]host:port` with `OUTPACE_PROXY_MODE=off|on|fallback`
  (default `off`). Outgoing peer connections and catalog/search requests use `CONNECT`; UDP
  trackers use `UDP ASSOCIATE` or are disabled, never sent direct; DHT is off while the proxy is
  active. `on` turns inbound serving and port mapping off (an explicit `1` for either is a startup
  error) and `outpace broadcast` refuses to run. `fallback` connects directly and switches
  engine-wide, until restart, the first time a live start finds no peers or none connects within
  10 seconds. Credentials never reach logs, errors or status. Stream status reports
  `network_path`, and `GET /network-policy` gains a `proxy` object. See
  [Outbound Proxy](https://github.com/outpace-stream/outpace-engine/wiki/Outbound-Proxy).
- **Stream start phase and typed failure codes**
  ([#487](https://github.com/outpace-stream/outpace-engine/pull/487),
  [#493](https://github.com/outpace-stream/outpace-engine/pull/493), closes #483).
  `GET /streams/{network}/{id}/status` adds `phase` (`resolving`, `connecting`, `buffering`,
  `playing`, `failed`) and `error`, and answers `200` for a start that is still resolving or
  failed in the last 60 seconds. Codes are `not_found`, `no_peers`, `network`, `unresolvable`,
  `protected`, `capacity`, `no_space` and `internal`.
- **VOD free-space check** ([#489](https://github.com/outpace-stream/outpace-engine/pull/489),
  closes #485). With `OUTPACE_CACHE_TYPE=disk`, a VOD start that would not fit on the cache
  filesystem is refused with `507 Insufficient Storage` and code `no_space`. The new
  `OUTPACE_VOD_DISK_RESERVE_BYTES` (default 256 MiB) sets the space to leave free. A download that
  hits `ENOSPC` or `EDQUOT` mid-way stops and answers `507` on later range requests.

## Changes

- **Native start errors are JSON.** `/streams/{network}/{id}`, `.ts` and `.m3u8` return
  `application/json` `{"error":{"code","message"}}` instead of a bodiless `404` or a plain-text
  `422`, as do `/vod/...` errors and native audio-normalization start failures. Status codes are
  unchanged. The compatibility `/ace/*` and `/server/api` surfaces are unchanged. Clients that
  parsed the old plain-text body should read `error.message` instead.
- **Faster DHT lookups** ([#490](https://github.com/outpace-stream/outpace-engine/pull/490)). A
  DHT walk keeps up to 8 queries in flight and sends the next one as soon as a reply, a BEP-5
  error or a 1.5 s slot timeout frees a slot, instead of waiting out a fixed 1.5 s round. A
  four-hop offline fixture fell from 4.5 s to under a millisecond; a silent frontier keeps the
  old pace. The `timeouts` field of the `[dht] walk done:` log line now counts silent queries,
  not silent rounds.
- A cancelled start whose provider then fails is no longer reported as `failed` by the status
  route (#493).

## Distribution

Targets, packages, images and signer identity are unchanged from
[1.0.2](https://github.com/outpace-stream/outpace-engine/blob/main/docs/releases/1.0.2.md#distribution).
Images are published to `ghcr.io/outpace-stream/outpace-engine` (`1.2.0`, `1.2.0-minimal`,
`latest`, `minimal`). The Compose file does not forward `OUTPACE_ENABLE_CAST` or the proxy
variables; casting from a container also needs `--network host`.

## Upgrade and rollback

Upgrading from 1.1.0 needs no configuration change. Restart, then check `/healthz` and playback.
Update clients that read the plain-text body of a native start error. Keep the 1.1.0 binary or
image for rollback; 1.2.0 writes no new state to the data directory.

## Validation and limits

The new features are covered by unit and HTTP tests: SSDP, device-description, SOAP and URL
parsing and the cast lifecycle; SOCKS5 negotiation, credential redaction and the fallback window;
start-phase transitions and error mapping; the free-space fit and the mid-download `ENOSPC` path;
and DHT slot pacing on loopback fixtures. Casting was exercised against a software renderer during
review. The DHT pacing was compared on live public channels during review (#490). No hardware TV
matrix, no proxy soak, no multi-hour playback soak and no hardware qualification was performed for
this release. Preparation checks and candidate
CI are recorded in [release PR #495](https://github.com/outpace-stream/outpace-engine/pull/495). The
[release workflow](https://github.com/outpace-stream/outpace-engine/actions/runs/43711547744)
completed successfully on 2026-11-15. All ten required archives and six packages matched
`SHA256SUMS`, and their attestations verified with `--repo outpace-stream/outpace-engine` against
the `v1.2.0` tag. Both optional Android archives matched their separate checksums; they are not
attested. Standard and minimal image indexes contain linux/amd64, linux/arm64 and linux/arm/v7;
`latest` and `minimal` match their versioned digests, and both image attestations verify. The
downloaded Linux x86_64 binary and both images report `outpace 1.2.0`, and the minimal image passed
`/healthz` and `outpace healthcheck`. These are publication checks, not playback acceptance.
